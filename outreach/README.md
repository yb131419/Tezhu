# 自動開發信原型（Google Apps Script + Gemini 免費層）

本資料夾是「自動開發信原型流程」的程式與設定說明。流程依序為：整理名單 → 產生草稿（Gemini）→ 人工審核 → 定時寄信 → 退訂 → 每日摘要。

**本原型不做自動爬取。** 名單請人工查到公開商務信箱後，貼入「名單」分頁。

## 檔案

- `自動開發信.gs`：所有程式（綁定在 Google Sheet 的 Apps Script 專案）

## 一、Google Sheet 分頁

建立一個 Google 試算表，建立以下四個分頁（名稱必須完全一樣）：

1. **名單**：第一列放欄位名稱。程式會自動補缺少的欄位。欄位包含：ID、公司名稱、公開資訊、產業、地區、公開商務信箱、來源網址、搜尋日期、狀態、草稿主旨、草稿內容、核准人、寄送時間、錯誤訊息、退訂代碼（退訂代碼由程式自動產生，不用手填）。
2. **退訂名單**：第一列放「信箱、退訂時間、來源」。
3. **設定**：第一列放「項目、值」，之後每列一個項目：

   | 項目 | 範例 |
   |---|---|
   | 每日寄信上限 | 20 |
   | 寄件人名稱 | （你的名字或品牌） |
   | 公司名稱 | （公司全名） |
   | 聯絡方式 | （電話或商務信箱） |
   | 退訂連結網址 | （部署後的網頁應用程式網址，見第四節） |
   | 通知信箱 | （你自己的信箱，用來收每日摘要與錯誤通知） |
   | 產品定位 | （一兩句話說明產品，會放進 AI 草稿的提示詞） |

4. **每日摘要**：第一列放「日期、寄出數、退訂數、錯誤數」，程式會自動寫入。

## 二、狀態說明

| 狀態 | 誰設定 | 意思 |
|---|---|---|
| 待產生 | 人工 | 要讓 AI 產生草稿 |
| 待審 | 程式 | 草稿已產生，等待人工審核 |
| 已核准 | 人工 | 審核通過，可以寄出 |
| 已寄出 | 程式 | 已寄出，會寫入寄送時間 |
| 已退訂 | 程式 | 收件人已退訂 |
| 略過 | 程式或人工 | 信箱重複、格式錯誤、在退訂名單中，或人工判定不寄 |

寄信前程式會確認：狀態必須是「已核准」，且信箱不在退訂名單中。寄信失敗時狀態維持「已核准」，下次會再試。

## 三、部署步驟

1. 在 Google Sheet 中點選「擴充功能 → Apps Script」。
2. 刪除編輯器裡原有的程式，把 `自動開發信.gs` 的全部內容貼上，按儲存。
3. 點左側「專案設定」（齒輪）→ 找到「指令碼屬性」→ 新增屬性：
   - 屬性：`GEMINI_API_KEY`
   - 值：在 Google AI Studio 建立的 API 金鑰
   - 金鑰只存在這裡，不要貼到程式碼或任何聊天視窗。
4. 回到試算表，重新整理頁面，選單會出現「小乖開發信」。第一次使用請點「建立欄位與觸發器」，並依提示完成授權。
5. 完成第四節的網頁應用程式部署，並把網址填入「設定」分頁的「退訂連結網址」。

## 四、退訂網頁應用程式（退訂連結）

1. Apps Script 右上角點「部署 → 新增部署作業」。
2. 類型選「網頁應用程式」。
3. 執行身分選「我」，誰可以存取選「任何人」。
4. 按「部署」，複製網址（結尾為 `/exec`），貼到「設定」分頁的「退訂連結網址」。
5. 之後修改程式，請用「部署 → 管理部署作業 → 編輯 → 新版本」，不要再「新增部署作業」，否則網址會改變，舊信件的退訂連結會失效。

## 五、Gemini 設定

- `自動開發信.gs` 預設使用 `gemini-2.5-flash`，位於程式最上方的 `GEMINI_MODEL`。免費額度與模型可用性依 Google 公告為準，若回報模型不存在，請改為 AI Studio 中目前可用的模型名稱。
- 草稿會經過 `BANNED_WORDS` 檢查，含療效或誇大用語就不會進入「待審」，錯誤訊息會寫在該列。寄出前也會再檢查一次。

## 六、每日運作

| 時間 | 動作 |
|---|---|
| 每小時 | 整理名單、為「待產生」的列產生草稿（每次最多 10 筆） |
| 每天 10:00 | 寄出「已核准」的信件（不超過每日上限，每封間隔 5 秒） |
| 每天 21:00 | 寫入每日摘要並寄到通知信箱 |

遇到 Gemini 或 Gmail 配額錯誤時，程式會停止本次執行並寄通知到通知信箱。

## 七、測試順序（依流程文件）

1. **第一輪**：在名單加入你自己的測試信箱，填好公司名稱，把狀態改為「待產生」，等草稿產生後檢查主旨、內容與退訂連結，再改為「已核准」，然後點選單「立即寄出已核准信件」。
2. **第二輪**：5 筆真實名單。
3. **第三輪**：擴大到 20 至 30 筆，觀察退信與退訂率。

## 八、已知限制

- 尚未在 Apps Script 實際執行測試，只通過語法檢查。第一次部署後請先跑第一輪測試。
- 退訂代碼對應列號的寫入沒有跨執行的鎖定，寄信與退訂同時進行的極端情況下可能有一筆狀態被覆寫，原型階段可接受。
- 寄信與退訂功能需要 Gmail 寄信權限；Google Workspace 的寄信額度通常高於一般 Gmail。
